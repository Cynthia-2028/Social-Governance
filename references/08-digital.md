# 数字治理：平台、算法与技术治理

本文件处理数字技术进入治理后的新问题：平台权力、算法不透明、数据治理、技术治理工具的两面性。依据等级：〔A〕多来源经验材料支撑；〔B〕单一来源经验或制度文本支撑；〔C〕概念推演，尚缺直接证据。涉及对具体国家制度评价的内容一律不收，本文件只保留分析工具与适用条件。

---

## 一、算法权力的不透明结构

**三种保密技术。** 对算法决策的不透明，可拆为三种技术的组合：真实保密（以物理与访问边界阻断访问）、法律保密（以法定义务与合同禁止披露）、混淆（保密被突破后以海量材料或复杂结构制造理解障碍）。三者共同产出的是可救济却难以救济的不可理解性，其特征是人为的、可改变的。〔B〕

**信息链上的三层黑箱。**

1. 来源层：数据从哪来、由谁拼装。数据经纪环节使来源不可追溯；错误画像跨系统流通，更正不级联，当事人须逐家请求。
2. 处理层：规则如何被计算。排序与评分规则以商业理由不公开；个性化使同一查询对不同人给出不同结果，用户无法知道看到的是哪一版。
3. 反馈层：结果如何回到人身上。不利决定的说明只有理由代码，点出因素不给权重；申诉需要先证明错误，而错误本身不可见。

三层互相加固：来源不可追溯使处理不可审计，处理不可审计使反馈不可争辩，反馈不可争辩又使用户失去发现来源错误的动机。〔B〕

**排序权力的隐蔽性。** 以降权而非删除进行惩罚：被降权者从自身位置检索时仍可能看到高位结果，因而难以察觉处罚。评估算法问责工具时，先问它能否处理降权这类不可见的处罚。〔B〕

## 二、平台的结构

平台指可编程的数字架构，用以组织用户间互动，并以系统化收集、算法处理、流通与货币化用户数据为目标。平台生态分层：

| 层 | 角色 | 权力形态 |
|---|---|---|
| 基础设施平台 | 控制接入与数据流通（搜索、云、支付、身份、应用商店） | 网关权与标准设定权 |
| 部门平台 | 面向单一部门撮合交易 | 定义权与免责权（以技术公司身份规避部门责任） |
| 补充者 | 提供实际供给（房东、司机、商户、内容生产者） | 承担供给风险，议价能力弱 |

分层是角色关系而非固定类型，同一行动者可随时间换位；层级间存在持续整合压力：基础设施平台向部门扩张，部门平台在掌握关键数据时上升为基础设施。混合身份是核心机制：兼具平台运营者与用户身份的行动者得以在公私二分之外活动，进入法律与社会灰区。〔B〕

## 三、平台化三机制

- **数据化**：把此前未被量化的世界转为数据。注意原始数据是矛盾修辞，数据总已被采集装置预先塑形。
- **商品化**：把对象、活动、情感、观念转为可交易商品，以注意力、数据、用户、金钱四种通货计价。多边市场结构有强烈垄断倾向：补贴与网络效应使一侧的吸引力足以俘获另一侧。
- **选择**：平台通过界面与算法触发并过滤用户活动；三种形态为个性化、声誉与趋势、审核。

三者成环：数据化为商品化提供原料，商品化为选择设定目标函数（留存、参与、广告库存），选择的结果回流为新数据。认识论核心是通约化：把不同质的东西转为同一度量。通约是政治的：它重建权威关系、创造新的解释框架。〔B〕

**对既有行业的重组。** 新闻业表现为拆包与再打包：内容、受众与广告被分离后由平台重新组合，重组者取得选择权；新闻组织以平台指标组织生产后，编辑自主性下降。交通业：数据化使此前交易成本过高的撮合可行，公共与私营模式在同一平台内被通约。医疗与教育：平台以个人获益加公共善的双重承诺换取数据，数据公地可能在形式自愿的条件下转为私有资产；规模化的实质是全球标准化。〔B〕

## 四、公共价值评估框架

评估平台与数字治理工具，可用一组公共价值维度。不存在普适清单，同一价值在不同领域含义不同，须逐领域操作化：

| 价值 | 观察点 |
|---|---|
| 隐私 | 数据流向可否追踪、条款可否理解、当事人可否访问自身档案 |
| 安全 | 泄露事件、加密与访问控制、单点失效风险 |
| 透明 | 算法规则、审核指南、营收与所有权结构是否公开 |
| 准确 | 错误率、事实核查、算法输出可否验证 |
| 公平 | 是否因无关属性区别对待、评分可否申诉 |
| 包容 | 无智能机、无银行卡人群可否获得服务、无障碍供给 |
| 团结 | 风险与成本在群体内如何分摊、从业者保障归谁 |
| 问责 | 有无主体能为后果负责、能否被追问 |
| 民主控制 | 规则制定是否经公共审议 |
| 可及与可负担 | 覆盖率、分区统计、补贴后价格 |

评分式应用须警惕两件事：维度权重由谁定；平台是否会以披露复杂度对冲透明要求（披露与反披露的递归）。〔B〕

## 五、技术治理工具的两面性

技术治理指以法治化、规范化、标准化、量化考核为核心的行政改革路径。数字技术放大了它的能力与代价：

1. **信息模糊性**：技术可缓解但不能根除信息问题，信息有模糊性、技术是双向的、条文带来繁文缛节。
2. **过程导向的转变**：数字技术降低信息不对称后，考核从结果导向转向过程导向、从政绩驱动转向问责驱动；过程监督强化而激励不足时，出现留痕、拍照、填报等形式化应对。
3. **指标替代**：可测量项优先、不可测量项搁置；代理指标重塑被测量的现实（纳税人改造行为以最小化被观察指标）。
4. **可读性的代价**：治理单元的简化（台账、网格、编码）只记录官方关心的事实，静态、聚合、标准化；纸面事实与地面事实会分叉，影子规则始终存在。
5. **挤出效应**：强管控介入自愿合作已存在的地方，可能削弱存量合作。

评估任何数字治理工具的四个问题：它解决的信息问题是否真实存在；填报与留痕成本落在谁身上；不可测量的工作被如何处置；它对存量自愿合作是补充还是替代。〔B〕

## 六、数据治理的三个要点

1. **更正的级联性**。错误数据的危害主要在下游复用，更正机制须能级联；逐家请求式更正把纠正成本转移给个人。评估数据治理制度，看更正能否自动扩散。
2. **推断的分类**。以倾向、担忧等推断形式作出的分类难以被证伪，难以进入准确性争议。规则上应区分事实性记录与推断性画像，并给后者设置不同的异议通道。
3. **评分的自实现**。评分同时用于定价或配给时，标签会改变被标者的处境，使预测自我实现。审查评分应用时，检查评分结果是否进入资源配置环节。〔B〕

## 七、政务数字化的特有风险

1. **统一身份的单点依赖**。统一认证提高效率，也使部门平台对单一身份供应商形成依赖；故障传导路径须事先测算。
2. **指尖上的形式主义**。政务应用数量膨胀、强制打卡、积分排名，把留痕成本转给基层与居民。评估指标：应用数量、强制事项占比、数据重复填报率。
3. **数据壁垒与部门利益**。数据共享的障碍多为利益而非技术：部门以数据为资源支配手段，共享即失去筹码。解法在设计层：以职责清单确定数据权属，而非要求部门自愿。
4. **算法辅助决策的边界**。辅助与替代的界限在于：不利决定有无人工复核、复核者是否有权改变结果、结果可否申诉。三者缺一，算法辅助即算法决定。〔C〕

## 八、可用作分析工具的判断

1. 平台生态的结构性特征是分层而非平面：基础设施控制接入，部门平台控制撮合，补充者承担供给与风险。
2. 平台治理的困难部分是语汇与管辖：现行制度以部门与公私二分为基础，而平台权力生成于这些区分的缝隙。
3. 声誉系统的效力不在于测量质量，而在于以停用相威胁塑造行为；阈值不公开使被评者只能猜测规则。
4. 一次错误判定会沿数据供应链扩散，而更正不会自动跟随。
5. 当平台以个人获益加公共善的双重承诺获取数据时，形式自愿不等于实质自愿。
6. 算法问责的核心诉求应从透明（披露一切）转向可理解与可争议（能解释、能纠正、能申诉），因为披露会被复杂度吸收。〔B〕

## 九、可操作的研究切口

1. 定价公平性：用可观测变量解释同一服务不同时段或区域的定价差异，分析不可解释残差的空间分布。
2. 申诉机制：平台把申诉改为纯自动化工单前后，申诉成功率与复议率的变化。
3. 指标落地：以民族志追踪一项量化指标进入基层台账后的行为再配置，重点看被指标排除的工作如何重组。
4. 统一身份依赖：以接口调用与故障数据做网络分析，度量部门平台对单一供应商的依赖。
5. 评分自我实现：评分阈值调整前后，被评者行为与退出率的事件研究。
6. 数据更正：引入级联更正机制前后，下游错误存留时间的变化。〔C〕
